# 인지 컨디션 체크 — UX/UI Smoke Test Report

실제 사용자 흐름을 브라우저(agent-browser, 390 / 768 / 1440px)로 처음부터 끝까지 따라가며 점검했고,
발견한 문제는 우선순위대로 코드에 반영한 뒤 같은 흐름을 다시 돌려 확인했다.
캡처는 전부 합성 데이터(자동 입력)이며 실환자 정보는 없다.

## 1. Executive Summary

- **Overall UX Readiness Score: 78 / 100**
- **출시 준비 상태**: P0·P1은 전부 수정했다. 남은 것은 P2 3건, P3 2건이며 기능을 막지 않는다.
  80점을 넘기지 않은 이유는 P2가 남아 있고, 실기기(iOS Safari) 확인이 아직 없기 때문이다.
- **가장 큰 UX 문제 (수정 전)**
  1. 반응속도·별똥별 게임에서 `준비됐어요` → `반응 시작` **연속 두 번 클릭** (P1, 매 판 2회 반복)
  2. 게임 7개 완료 뒤 주 버튼이 `한 판 더`였다. 제품의 핵심(기준선을 만드는 3분 측정)이 보조 줄에 숨어 있었다 (P1)
  3. 3분 측정 결과 화면의 `홈으로` 버튼 — 홈 탭은 없어졌다 (P1, 신뢰)
  4. 정답일 때 자동으로 넘어가지만 그 사실을 알리는 타이머 바 CSS가 없어 **보이지 않았다** (P2)
  5. `나의 변화` 빈 상태가 측정 기록도 없는데 저장 동의부터 요구했다 (P2)

## 2. 점검한 사용자 여정

```
플레이(난이도 선택) → 게임 7개 시작 → 안내 → 이야기 읽기(25초) → 질문 4개 → 반응속도 6회
→ 숫자 뒤집기 3문제 → 색깔 단어 6문제 → 이야기 다시 퀴즈 4문제 → 패턴 6문제 → 별똥별 6회
→ 게임 결과 → 3분 집중 측정(연습 3회 → 본 측정 3분) → 측정 결과 → 저장 동의 → 나의 변화
```

보조 여정: 게임 안내 탭, 그만두기 확인, 기록 모두 삭제 확인, 측정 품질 실패 결과.

## 5. 남은 항목 (미수정)

- **P2 · 플레이 첫 화면 위계** — 1초 테스트에서 눈이 난이도 4줄에 먼저 간다. "5분이면 끝나요"와 주 버튼이 그 아래다.
  난이도를 접힌 한 줄(현재 선택만 표시)로 바꾸는 안을 검토할 수 있다. 이번엔 이전 세션의 의도적 설계라 보존했다.
- **P2 · 경계 문구 반복** — 같은 `notice-box` 5줄이 게임 안내·나의 변화·측정 결과 세 곳에 그대로 반복된다. 의료 경계라 지우지 않았고, 탭별로 한 줄로 줄이는 것은 Sylvie 결정이 필요하다.
- **P2 · 반응속도 게임에 놓침 제한이 없다** — 원이 뜬 뒤 6초 뒤에 눌러도 그대로 기록된다(별똥별은 3초 놓침 처리). 게임 로직이라 손대지 않았다.
- **P3 · 게임 안내 접힘 라벨** `무엇을 보고 무엇을 못 보나요` — 뜻은 맞지만 길다.
- **P3 · 실기기 확인 없음** — iOS Safari 키보드가 숫자 입력 버튼을 가리는지 미확인.

## 6. UX Debt / Design System Debt

- 버튼 클래스가 `primary-button` / `lime-button` / `ghost-button` / `quiet-button` / `danger-button` / `pvt-row` 여섯 가지다. `primary`와 `lime`은 색이 같고 크기만 다르다 → 하나로 합칠 후보.
- `progress-track`가 안내 카드·이야기 타이머·기준선 진행에 세 가지 의미로 쓰인다.
- `.level-tile`, `.side-card`, `.app-hero`, `.brand-mark`, `.link-button`, `.transition-icon`, `.hero-status`, `.hero-cta` 등 참조 없는 CSS가 남아 있다(삭제 후보).
- 카드 radius가 12·16·20px 세 가지다(회사 규칙 상한 16px).
